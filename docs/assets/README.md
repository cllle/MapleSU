# Brand assets

The artwork in [`brand/`](brand/) is rendered by [`tools/brand/render_brand_banners.py`](../../tools/brand/render_brand_banners.py), a Pillow port of the Manager's banner renderer in `manager/src/main/java/com/maplesu/core/ui/component/maple/`. It reproduces the in-app tokens, palettes, glyph coverage, motion field and seeded noise, so the documentation and the Manager show the same artwork.

| File | Size | Use |
| --- | --- | --- |
| `brand/maplesu-dark.png` · `brand/maplesu-light.png` | 1800 × 520 | README header: the About MapleSU wordmark, with the credits microprinted inside the glyphs |
| `brand/ultra-dark.png` · `brand/ultra-light.png` | 1032 × 288 | Ultra mode banner: square grid in Ultra violet |

| `brand/community-{zh,en}-{dark,light}.png` | 1200 × 208 | The About dialog's channel line: Telegram · @KernelMapleSU |
| `brand/social-preview.png` | 1280 × 640 | Repository social preview (Settings → General → Social preview) |
| `banner.png` | 1032 × 300 | Original capture of the Manager's About MapleSU banner |
| `advisors/wall.svg` | 507 × 524 | Avatar wall of the MapleSU User Advisor Program in both READMEs; generated, see [below](#user-advisor-program-wall) |

Every image except the social preview has a transparent background. Pair the dark and light files with `<picture>` so each GitHub theme gets its own palette:

```html
<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/assets/brand/maplesu-dark.png">
  <img src="docs/assets/brand/maplesu-light.png" alt="MapleSU" width="720">
</picture>
```

## Regenerating

Change the Manager tokens first, mirror the change in the script, then render again:

```shell
python3 tools/brand/render_brand_banners.py --fonts /path/to/android-fonts
```

The script needs Pillow and the Android platform fonts the Manager renders with on a stock device: Roboto, Droid Sans Mono and Noto Sans CJK. They are not stored in this repository. Robolectric's `nativeruntime-dist-compat` artifact, which the Gradle cache already holds for the Manager's tests, contains them under `fonts/`. Use `--only` to render selected pieces.

## User Advisor Program wall

`advisors/wall.svg` and the member tables between the `advisors:start` and `advisors:end` markers in both READMEs are generated by [`tools/brand/render_advisor_wall.py`](../../tools/brand/render_advisor_wall.py) from the roster the Manager ships: [`members.json`](../../manager/src/main/assets/maplesu/advisors/members.json) and one picture per member in `avatars/`, named after the member's `id`. The About MapleSU dialog reads the same files at runtime, and `AdvisorRoster.kt` seats the members and sizes the avatars exactly as the script does, so both walls stay identical. Edit the roster, never the outputs:

```shell
python3 tools/brand/render_advisor_wall.py          # validate the roster, then rewrite wall.svg and both README tables
python3 tools/brand/render_advisor_wall.py --check  # fail if any output is stale; the tool tests run this
```

Only the standard library is needed. Avatars are square JPEG or PNG files of 120 to 320 px and at most 40 KiB; only members with a picture are listed. A new tag needs a badge in the script's `TAG_BADGES` and a look in `TAG_LOOKS` in `manager/src/main/java/com/maplesu/core/ui/screen/home/AdvisorWall.kt`. The SVG embeds the pictures and animates with CSS only, because GitHub shows README images without scripts or external files.

The avatars belong to the members who chose them and are shown only to credit them; they are not covered by the repository license. A member who wants a picture changed or removed can ask the maintainer, and it is taken out of the roster.
