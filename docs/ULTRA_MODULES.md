# Ultra 原生模块开发指南

Ultra 原生模块是 ARM64 原生共享库，由对应后端读取描述信息并执行。它与应用侧 Binder SDK、KSU 脚本模块和 Linux `.ko` 的接口不同。

当前公开整理范围包含 Manager 的识别、路由和管理代码；历史原生 SDK 的头文件、静态库与派生工件未作为可公开分发的 SDK 发布。没有已确认的公共 SDK 版本时，不将本地集成版本号视为对外 ABI 承诺。

## 开发前确定输入

| 输入 | 需要确认的内容 |
| --- | --- |
| SDK 来源 | 原作者、公开分发许可、固定版本、对应源码与文件摘要 |
| 加载器 | 目标 MapleSU 版本、Ultra 后端与模块生命周期契约 |
| 设备 | Android 版本、ARM64、内核版本与所需内核接口 |
| 身份 | 首次生成后保持不变的 32 位 ASCII 字母数字模块 ID |
| 元信息 | 名称、版本、作者、描述、更新入口与许可 |

SDK 的底层 API 名称沿用其实际 ABI。当前维护路线保留现有后端和模块接口，构建输入与升级步骤见[后端依赖与维护](NATIVE_DEPENDENCIES.md)，组件来源见[致谢](../CREDITS.md)。应用侧 Binder SDK 的版本与原生模块 ABI 分别维护。

## 包布局

```text
libmodule_example.so
payload/
    module.prop
    LICENSE
    README.md
webroot/
    index.html
```

共享库位于 ZIP 根目录；市场元信息放在 `payload/module.prop`，避免与根目录 `module.prop` 的 KSU 类型识别冲突。WebUI 和其他资源按模块实际需要提供，脚本不是原生入口的替代品。

原生库需要符合 ELF64、小端、AArch64、ET_DYN 形态，并包含当前后端接受的真实导出入口和描述信息。Manager 还检查入口可见性、可执行段、字段边界、UTF-8 和模块身份；普通字符串或未定义导入符号不作为有效入口。

## 构建与生命周期

1. 从有明确分发许可的 SDK 获取该版本接口和工具链要求；固定输入版本与摘要。
2. 通过 SDK 的实际描述接口声明元信息、固定 ID 与入口。保留原接口来源和组件许可。
3. 构建 ARM64 共享库，保留加载器需要的导出符号和描述节。不要在验证前剥除节表或重写描述字段。
4. 入口只执行有界初始化并尽快返回；耗时操作等待所需系统服务就绪后另行处理。
5. 安装、升级、禁用、卸载和异常退出分别验证。涉及后台任务时验证重复启动、资源释放和重启后的状态。

与内核数据结构或版本绑定的能力应先做支持范围检查；不支持的组合返回明确失败，不将静态识别成功呈现为运行成功。

## 静态检查与测试

仓库中的形态检查工具只读取包，不执行模块：

```shell
python tools/check_module_shape.py example-module.zip
```

该工具用于辅助判断原生/脚本形态和明显的格式歧义，不替代生产 Manager 的完整校验、SDK ABI 检查或设备验证。设备验收至少覆盖首次安装、更新、重启、禁用、卸载及失败恢复，并记录加载器与 SDK 的真实版本。

## 兼容判定

静态检查、已确认不兼容、未验证和按动作实测通过分别处理。现有固定规则与记录范围见[模块兼容判定](MODULE_COMPATIBILITY.md)。

## 提交市场

按[模块仓库指南](MODULE_REPOSITORY.md)提交原始 ZIP、源码、许可、摘要和兼容性说明。原生 ID 必须与库内描述一致，版本更新复用同一 ID。未确认再分发范围的 SDK 或原生库只记录来源，不作为公共仓库附件上传。
